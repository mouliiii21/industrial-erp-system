## overview

Industrial ERP System

A full-stack resource-planning system that runs the sales side of a manufacturing business end to end — from the moment a customer enquires about a product to the moment stock leaves the warehouse. Built on PostgreSQL, Express, React and Node, with the backend as the sole source of truth for pricing, permissions and stock.

Enquiry→ Quotation→ Accepted→ Sales Order→ Reservation→ Dispatch
View source Run it locally

Originally scoped as a 48-hour full-stack technical case study — enquiry-to-dispatch workflow, role-based access, and concurrency-safe inventory, built in roughly 10–14 hours of active work.

## features

What it does

Every screen maps to a stage of the sales workflow. Role checks, pricing math and stock math all happen on the server — the frontend never has the final say.

Auth & access

  • JWT-based login
  • Passwords hashed with bcrypt
  • ADMIN / SALES roles
  • Every protected route checked server-side

Enquiries

  • Log a customer enquiry
  • Multiple line items per enquiry
  • Linked to customer and product records

Quotations

  • Generated from an enquiry
  • Totals calculated server-side — never trusted from the client
  • Status-driven: draft → accepted
  • Accepted quotes convert into orders

Sales orders

  • Created from an accepted quotation
  • One order per quotation, enforced
  • Confirm, dispatch or cancel

Inventory

  • Tracks physical vs. reserved stock
  • Available = Physical − Reserved
  • Reservation is transaction-safe under concurrent requests
  • Blocks reservation when stock is short

Dispatch

  • Ships reserved stock
  • Updates physical & reserved quantities in one transaction
  • Can't dispatch more than was reserved
  • Cancellation releases the reservation
## roles

Who can do what

ADMIN
  • Confirm, dispatch and cancel sales orders
  • Update physical inventory quantities
  • View the full sales pipeline
SALES
  • Create and manage customer enquiries
  • Create quotations and change their status
  • Convert accepted quotations into sales orders
  • View inventory availability (read-only)

All of the above is enforced in backend middleware, not just hidden in the UI — calling a protected endpoint directly without the right role still fails.

## database

Database design

A normalized PostgreSQL schema — twelve tables connected by foreign keys, unique constraints and CHECK constraints — modelling the same pipeline the UI walks through: a customer's enquiry fans out into items, an enquiry turns into a quotation, an accepted quotation becomes at most one sales order, and a sales order's items get reserved and eventually dispatched.

## security

Security & data integrity

  • JWT authentication with an expiring token
  • Passwords hashed with bcrypt, never stored in plain text
  • Role-based authorization enforced on the backend, not the UI
  • Request bodies validated with Zod before they touch a query
  • Parameterized queries throughout, via Knex.js
  • Foreign key, unique and CHECK constraints at the database level
  • Quotation totals computed server-side, immune to client tampering
  • Inventory reservation wrapped in database transactions

## decisions

Technical decisions

Backend-calculated quotation totals

The client sends quantities and prices; the server recomputes the total independently before it's stored. A tampered request body can't change what gets billed.

Transaction-safe inventory reservation

Reserving stock is a conditional update inside a transaction — it only succeeds when physical_qty − reserved_qty ≥ requested_qty holds at the moment of the write. Two requests racing for the last units can't both succeed.

Normalized relational schema

Twelve linked tables with foreign keys and constraints, rather than a looser document shape — appropriate for data where referential integrity (one order per quotation, valid product references) actually matters.

Backend-enforced RBAC

Role checks live in Express middleware, not component visibility. Hiding a button isn't access control; a direct API call from a SALES account still gets rejected on an ADMIN-only route.

## setup

Running it locally

  1. Prerequisites

    Node.js, npm, and PostgreSQL 16+ installed locally.

  2. Install dependencies

    cd server && npm install
cd ../client && npm install

  3. Configure environment

    Create server/.env from .env.example with your database URL, JWT secret and port.

  4. Create & migrate the databases

    createdb erp_case_study
createdb erp_case_study_test
npm run migrate
npm run seed

  5. Start both servers

    # server/  → http://localhost:4000
npm run dev

# client/  → http://localhost:5173
npm run dev

  6. Sign in with a seeded account

    admin@erp.test / Admin@123 for the ADMIN role, or sales@erp.test / Sales@123 for SALES. Local/demo credentials only.
